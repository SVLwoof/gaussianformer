# Cleanup for the paper codebase (start after the full-data run, ~2026-09-28)

Goal: the repository contains the final method only, with few flags and few comments, and produces the same outputs
as before. Source: the 2026-09-25 code review (findings summarized below) and the user's decisions.

## Decisions (user, 2026-09-25)

- Old experiment checkpoints need not load in the new code. Tag the last pre-cleanup commit `pre-cleanup`; old
  renders or data come from `git worktree add ../old_gaussianformer pre-cleanup` when needed. No legacy module.
- `training/train.py` (two-phase, released models) and `training/train_full.py` (current) stay separate scripts.
  Both lose most flags: the recipe becomes constants in code; the CLI keeps data paths, save dir and step count.

## Preconditions

1. `gf_full` finished (`DONE_FULL step 375000`) and the final decay branch + evals are logged.
2. No job of ours is running from this working tree (cleanup rewrites files a running job imports).
3. `v20/placement` merged into `main` (it merges cleanly as of 2026-09-24); cleanup branch `v21/cleanup` off `main`.

## Step 0: freeze and golden outputs

- `git tag pre-cleanup` on the merged `main`; push the tag.
- Golden script (scratch, not committed): for V17b and the final full-data checkpoint, render 2 held-out objects x 2
  views at bf16 with fixed seeds and save the tensors; also save one `train_full` step's loss on a fixed batch.
- After every step below: re-render and assert max |diff| == 0 (bf16, same kernels) or document why not
  (e.g. the precision fix changes fp16 defaults on purpose). Run `tests/*.py` (CPU, `ATTN_IMPL=sdpa`).

## Step 1: correctness fixes

| # | File | Fix |
|---|---|---|
| 1 | `infer_gaussian.py`, `rendering_pipeline.py` | default precision bf16 (what training and evals use); `fp32` means fp32 in the view stage too |
| 2 | `rendering_pipeline.py`, `infer_gaussian.py`, README | output is display-referred [0,1] (trained on clipped gsplat PNGs): call it LDR, write PNG only, drop EXR/tone mappers; stop re-running `freeimage.download()` per view |
| 3 | `training/train.py` | `--pe_type` default `rope` (then the flag goes away with step 2) |
| 4 | `process_full.py`, `multi_radius_full.py`, `prune_recovery.py` | round, don't truncate, when writing uint8 GT (affects future data only; note it in PROGRESS) |
| 5 | `utils/transform.py` | `F.normalize` for quaternions (padded zeros -> NaN at batch > 1) |
| 6 | `gaussian_scene_processor/` | delete (orphaned, wrong normalization, reads raw PLY values unactivated) |

Not changed: object normalization by max |mean| (floater sensitivity). It defines the existing data; changing it means
regenerating 27k objects. Mention as a limitation.

## Step 2: remove dead options

From `GaussianFormerConfig` and the code paths behind them: `canvas_cond`, `value_rope_2d*`, `shape_rope_2d*`,
`log_cov_input`, `input_mlp_hidden`, `pe_type` (keep RoPE only), `view_transformer_use_swin_attn`, `include_alpha`,
`use_ldr`, `use_dpt_decoder` (keep DPT), `rope_double_max_freq`, `ray_self_rope_2d`, `vdir_pe_type`, `pos_dim`,
`gaussian_dim`, `turn_to_cam_coord`, `ray_rope_2d_dim/scale` if fixed. Decide per option whether the final recipe value
becomes a constant (e.g. `proj_rope_2d` always on) or stays a real option (`patch_size`, `xattn_window`).

Checkpoint loading: `config_from_checkpoint` drops removed keys whose stored value equals the recipe value and raises
("use old_gaussianformer") otherwise. V17b and the full-data checkpoints must load; the golden test proves it.

Also: `training/weight_transfer.py` builds a whole RenderFormer only to list parameter names (use the state-dict keys);
`training_forward` in `train.py` duplicates `GaussianFormerRenderingPipeline.render` (one function for both).

## Step 3: flags

- `train_full.py`: recipe constants (lr, warmup, loss weights, fg weight, save cadence) move into a small frozen
  dataclass at the top of the file; CLI = `--data`, `--val`, `--save_dir`, `--init_from/--resume_from`, `--steps`,
  `--decay_steps`, `--resolution`.
- `train.py`: same treatment; drop the modes no released model used.
- Shell scripts shrink accordingly; `probe_n10.sh` and the probe harness move out of the paper tree or are deleted
  (they served the architecture search, which is over).

## Step 4: comments

(`transform.py` quaternion order and `roma.unitquat_mul` remark; RenderFormer "flatten triangles" leftovers).
Keep: tensor shapes and conventions (wxyz vs roma xyzw, Blender camera), LPIPS in fp32, zero-init warm-start rule,
DDP-after-freeze, the windowing docstring.
